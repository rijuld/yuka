# yuka

Point your phone at a packaged-food label, get a nutrition score out of 100 and a short list of
ingredients worth knowing about — each with a concrete reason, not vague hedging.

The app runs entirely in the browser: OCR happens on-device with [Tesseract.js](https://tesseract.js.org),
and the ingredient parsing and scoring are done by Google's Gemini API.

> **Demo project — not medical advice.** Scores are generated by a language model and can be wrong.

---

## How it works

Everything is one automatic pipeline, kicked off the moment you pick a photo:

| # | Stage | Where it runs | What it does |
|---|-------|---------------|--------------|
| 1 | **Read** | On-device (Tesseract.js) | OCRs the label photo into raw, noisy text |
| 2 | **Extract** | Gemini | Pulls just the ingredient list out of that OCR text |
| 3 | **Score** | Gemini | Returns `{ score: 0–100, harmful: [{ ingredient, why }] }` |

The scoring prompt explicitly forbids generic wellness language — a flagged ingredient must name a
real mechanism (sodium and blood pressure, added sugar and blood glucose, nitrites and processed
meat) or it gets dropped from the list. See [`src/ingredientsModel.ts`](src/ingredientsModel.ts).

## Tech stack

- [React 19](https://react.dev) + [TypeScript](https://www.typescriptlang.org)
- [Vite 8](https://vite.dev) for dev server and bundling
- [Tesseract.js](https://tesseract.js.org) for in-browser OCR
- [Gemini API](https://ai.google.dev/gemini-api/docs) (`gemini-3.1-flash-lite-preview`)
- [Playwright](https://playwright.dev) for end-to-end tests
- [ESLint](https://eslint.org) with `typescript-eslint` and the React Hooks plugin

## Getting started

### Prerequisites

- **Node.js** `^20.19.0 || >=22.12.0` — required by Vite 8
- A **Gemini API key** from [Google AI Studio](https://aistudio.google.com/apikey)

### Install and run

```bash
git clone https://github.com/rijuld/yuka.git
cd yuka
npm install

# add your key
echo "GEMINI_API_KEY=your_key_here" > .env

npm run dev
```

Then open the URL Vite prints (default <http://localhost:5173>) and upload or shoot a label photo.

### Configuration

Create a `.env` file in the project root:

```ini
# Either name works — GEMINI_API_KEY takes precedence
GEMINI_API_KEY=your_key_here
```

| Variable | Required | Description |
|----------|----------|-------------|
| `GEMINI_API_KEY` | yes | Gemini API key. Read by `vite.config.ts` and inlined at build time |
| `VITE_GEMINI_API_KEY` | — | Fallback name, used only if `GEMINI_API_KEY` is unset |

> [!WARNING]
> **This is a client-only app, so the key ends up in the JavaScript bundle.** Anyone who loads a
> deployed build can read it. That is fine for local development and throwaway keys, but before
> shipping this publicly you should put the Gemini calls behind a small server (or an edge function)
> and keep the key there. At minimum, restrict the key in Google AI Studio and set a spend cap.
>
> `.env` and `.env.*` are already git-ignored — never commit your key.

## Scripts

| Command | What it does |
|---------|--------------|
| `npm run dev` | Start the Vite dev server with HMR |
| `npm run build` | Type-check (`tsc -b`) and produce a production build in `dist/` |
| `npm run preview` | Serve the built `dist/` locally |
| `npm run lint` | Run ESLint across the project |
| `npm run test:e2e` | Run the Playwright end-to-end suite (starts its own dev server on port 5174) |

## Project layout

## Contributing

Contributions are welcome — issues and pull requests both.

1. Fork the repo and create a branch: `git checkout -b my-change`
2. Make your change, then make sure the checks pass:
   ```bash
   npm run lint
   npm run build
   npm run test:e2e
   ```
3. Commit with a clear message and open a pull request describing the change and how you tested it.

A few things that would genuinely help:

- Move the Gemini calls behind a server so the API key is not shipped to the client
- Refresh `e2e/ingredients.spec.ts` — it still asserts against an older version of the UI
- Better OCR preprocessing (cropping, contrast) for photos of curved or glossy packaging
- Accessibility passes on the score screen

Please keep the existing code style: TypeScript throughout, no semicolons, single quotes.
